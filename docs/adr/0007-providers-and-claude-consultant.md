# 0007. More providers, vision grounding, the Claude consultant and Jev carriers

- Status: proposed
- Date: 2026-10-01

## Context
Phase 6 (plan §7) adds Anthropic and Google keys with native computer tools for `vision_grounder`, OpenRouter, local OpenAI-compatible servers with discovery, a Claude Code consultant, Jev through other carriers, and a logprob decision emulation. The research notes (`model-layer.md`, `openrouter-jev.md`, `cli-agents.md`, `license.md` §4) set the direction and leave the choices below open.

## Decision
- **Provider packages.** `@ai-sdk/anthropic` 4.0.71, `@ai-sdk/google` 4.0.87 and `@ai-sdk/openai-compatible` 3.0.62, all Apache-2.0 and fetch-based. OpenRouter chat models go through `@ai-sdk/openai-compatible` (base `https://openrouter.ai/api/v1`), not `@openrouter/ai-sdk-provider`: one fewer dependency, and a metadata extractor reads `usage.cost` (usage accounting is requested per call). The provider-reported cost beats the catalog price. Keys come only from the engine env file or process env: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY` (or `GOOGLE_API_KEY`, `GEMINI_API_KEY`), `OPENROUTER_API_KEY`.
- **Local discovery.** `GET {baseURL}/models` on the servers listed in `models.local` and, when `models.discoverLocal` is on (default), on `127.0.0.1:11434` (Ollama) and `127.0.0.1:1234` (LM Studio). Nothing else is contacted; no port or network scan. Discovered models enter the catalog as free, text-only, 32k-context models; users mark vision or grounding conventions with catalog overrides.
- **Default bindings.** With no `models.roles`, each keyed provider appends its models after the OpenAI chain (Anthropic: Sonnet 5.5, Haiku 4.5 for the writer; Google: Gemini 3.8 Flash, 3.5 Flash-Lite for the writer; OpenRouter: GPT-6.1 Sol / GPT-6 Luna, no grounder). Local models are never bound by default.
- **Vision grounding.** One `VisionGrounder.groundTarget({screenshot, instruction})` in `@ghosthand/models` returns a protocol capture target `{captureId, x, y}` in image pixels, or `found: false` with a reason. Per model in the `vision_grounder` chain it uses the simplest documented API: Anthropic `computer_toolset_20260801` (Claude 5.5 and the toolset family) or `computer_20251124`, the OpenAI Responses `computer` tool, otherwise a JSON answer via structured output on the model's grid (pixels, 0–1000, 0–999). The vendor action is read, never executed, and no tool result is sent back. Points from Claude are scaled back when the API would have downscaled the screenshot (long edge > 1568 px or > 1.15 MP). A pending OpenAI safety check returns `found: false`; GhostHand never acknowledges it.
- **Gemini computer use is deferred.** It exists only on the stateful Interactions API, which `@ai-sdk/google` 4.0.87 exposes without a tool factory. Gemini grounds through the JSON path on its 0–999 grid until that lands.
- **Claude consultant.** `ClaudeConsultant` spawns the user's own, unmodified `claude` binary with `--print --input-format stream-json --output-format stream-json --verbose --tools "" --permission-mode dontAsk --strict-mcp-config --setting-sources "" --no-session-persistence --system-prompt … [--model] [--effort] --json-schema …`, verified against Claude Code 2.1.285. Never `--bare` (it ignores the user's login) and never a bypass flag. `--json-schema` is fixed per process, so a session keeps one warm process per schema. `probe()` runs `claude --version` and `claude auth status` and keeps only `loggedIn`, `authMethod`, `apiProvider` and `subscriptionType`. Variables of a parent Claude Code session are stripped from the child env. It is **opt-in** (`consultant.claude.enabled`, default false) or selected with `--planner claude`.
- **Anthropic policy.** Anthropic's terms do not allow third-party apps to use Claude Free/Pro/Max OAuth tokens or to offer Claude.ai login, and allow an end user to run the unmodified Claude Code binary with their own subscription (`cli-agents.md` §2, `license.md` §4). GhostHand therefore never reads, stores or forwards Claude credentials, never reads `~/.claude`, offers no Claude sign-in, does not use `@anthropic-ai/claude-agent-sdk`, and calls the consultant rarely (planning, not per step). Users either have API billing (an `ANTHROPIC_API_KEY`, the recommended path, which also gives the native computer tool) or run their own CLI login. Anthropic can change these terms without notice; check them before each release.
- **Jev carriers.** `decision.provider` is `typesafe` (default), `openrouter` (`https://openrouter.ai/api`, `typesafe/jev-1.13`, 32k context for the whole request, `usage.cost`) or `vercel` (`https://ai-gateway.vercel.sh/typesafe`, `typesafe-ai/jev`, cost from `provider_metadata.gateway.cost`), all through the TypeSafe SDK with a different base URL. `decision.apiKeyEnv` names the key; defaults are `TYPESAFE_API_KEY`, `OPENROUTER_API_KEY`, `AI_GATEWAY_API_KEY`. `decision.fallback` adds a `FallbackDecisionProvider` that asks the second carrier only after `rate_limit`, `overloaded`, `server`, `network` or `timeout`, never after `auth`, `invalid`, `too_large`, `budget` or an abort. Both share one spend cap and advertise the stricter limits of the two.
- **Logprob decisions (experimental).** `createLogprobDecisionProvider` emulates `noul` and `choice` over an OpenAI-compatible model that returns `logprobs`: one parallel call per question, state in the system message, a one-token answer (`Y`/`N`, letters `A`–`T`), probabilities from the top-20 logprobs renormalised over the allowed labels, TypeSafe's confidence formula, `calibration: "logprob"`. `score` and choices with more than 20 options are rejected. It is not wired into the engine config yet.

## Consequences
- Native grounding works only on direct Anthropic and OpenAI keys. Whether OpenRouter passes vendor computer tools through is unverified, so OpenRouter models are not bound as grounders.
- Gate thresholds tuned on Jev must not be reused for the logprob emulation without measurement.
- The Claude consultant draws on the user's Claude plan limits and can stop working if Anthropic changes its terms; Codex and API-key models remain the planner fallbacks.
- Live calls through Anthropic, Google, OpenRouter, Vercel and local servers are unverified until keys are available; tests use recorded or inline responses only.
