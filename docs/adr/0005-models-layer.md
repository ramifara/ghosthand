# 0005. Models layer: role chains, fallback rules and catalog

- Status: proposed
- Date: 2026-10-01

## Context
P1-02 adds `@ghosthand/models`: an AI SDK v7 wrapper with an OpenAI (Responses API) provider, role bindings with fallback chains, a models.dev catalog and a cost cap. The plan (§2, §3.1, §6 P1-02) and `docs/research/notes/model-layer.md` set the direction. They leave some details open, and the code needs an answer for each one.

## Decision
- **Fallback rules.** A role binding is an ordered list of `provider/model` refs. The next model is tried after `not_configured`, `auth`, `rate_limit`, `timeout`, `schema_failed`, `server`, `network` or `unknown`. The chain stops on `aborted` (the caller asked), on `budget`, and on `refused`, because a second model is not a way around a safety decision. SDK retries default to 0, so the chain does the retrying. Timeouts apply per attempt.
- **`budget` error kind.** `ModelError` gets a `budget` kind next to the kinds in the task. A shared `ModelCostMeter` checks a lower-bound input-cost estimate before each attempt and records priced usage after it, failed parses included.
- **Role requirements** (checked against the catalog, `Result` error otherwise):

  | Role | Requirements |
  |---|---|
  | planner | structured output, ≥ 64k context |
  | writer | ≥ 16k context |
  | vision_reviewer | structured output, image input, ≥ 32k context |
  | vision_grounder | image input, a native computer-use tool or a known grounding convention, ≥ 32k context |
  | judge | structured output, image input, ≥ 64k context |

  A call that carries images also needs image input. Models in a chain that don't qualify are skipped and logged. `validateBindings` reports all of them at startup. `decision` and `speech` are declared but rejected here.
- **Privacy.** OpenAI calls send `store: false`. Logs carry role, model, tokens, latency, cost and error kind, never prompts, images or request bodies.
- **Catalog.** The committed snapshot is generated by `scripts/models-snapshot.ts`. It reads a models.dev checkout (TOML, resolving `base_model` like upstream) or fetches `api.json`, and keeps only chat models (text in, text-only out, tool calling, not deprecated) for openai, anthropic and google. From OpenRouter it keeps models from ten major vendors released on or after 2025-09-01. A missing `structured_output` counts as false. Our own fields (computer-use tool, grounding convention, measured latency) are built in for the models named in the research note, and user overrides win field by field. Long-context price tiers are not modelled yet.
- **Default bindings.** These are placeholder bindings on the GPT-6 tier until P1-12 measures: planner and judge `gpt-6.1-sol` then `gpt-6-sol`; writer and vision_reviewer `gpt-6-luna` first; vision_grounder `gpt-6.1-sol` then `gpt-6-astra` (both have OpenAI's computer tool).

## Consequences
- A refusal or a spend cap surfaces to the caller at once, never as a silent switch to another vendor.
- OpenRouter prices and the computer-use list go stale. Re-run `bun run models:snapshot` and update the built-in fields when vendors ship.
- Anthropic, Google, OpenRouter and OpenAI-compatible are named `ProviderKind`s with no factory. Phase 6 adds the factories and the `@ai-sdk/*` dependencies.
